Key Technical Details

Aspect Detail
Runtime Single Python process, canvas_bot.main
Slack connection Socket Mode (outbound WebSocket via SLACK_APP_TOKEN) — no public URL or port
LLM Groq llama-3.3-70b-versatile, temperature 0.2
MCP bridge canvas-mcp-server spawned as stdio subprocess per agent run; ~92 tools, 15 whitelisted
Timeouts GROQ_TIMEOUT=30s · TOOL_TIMEOUT=25s · AGENT_TIMEOUT=75s · MAX_STEPS=6
Auth Per-user Canvas tokens, Fernet AES encrypted at rest
Storage SQLite locally (data/creds.db), Postgres on Railway (DATABASE_URL)
Write safety Course-visible writes gated by ✅ Confirm / ✖️ Cancel buttons; private planner notes written directly
Memory Stateless — conversation context re-read from Slack thread on every mention (last 20 messages)
Retry dedupe client_msg_id-based, in-memory OrderedDict (cap 500)
Rate limiting Per-user 15s cooldown on agent runs
Deployment Multi-stage Docker build → Railway (worker, ON_FAILURE restart)
Scheduler APScheduler cron trigger for daily Canvas digest
